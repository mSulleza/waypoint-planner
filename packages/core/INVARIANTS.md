# Invariants

The old app's 218 rules and how v1 keeps each one (spec §12). Numbers follow the file order of the discovery list, which is kept outside the repo with the design files. Each rule has exactly one owner task from the board and a status.

- **Rule** restates the old rule in general terms, without amounts, names or banks.
- **Owner** is the board task that closed the rule. P1-1, the task that wrote this map, owns the rules dropped outright.
- **Status** says how v1 keeps the rule: `test: <test file>: <test name>`, `database check: <name>` or `structure: <why>`, joined by `;` when several hold.
- `dropped: <reason>` means v1 does not need the rule; spec §2 lists what v1 leaves out. `partly dropped: <reason>` says how v1 changes the rule, and the test or check for the part that stays follows after a `;`.

P1-3 owns rule 207; P3-8 applies it to patches. `packages/core/test/invariants.test.ts` fails when a rule has no status, or when a cited test or database check does not exist.
